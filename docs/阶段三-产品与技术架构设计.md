# 桃江闪途项目 2.0｜阶段三产品与技术架构设计

> 状态：设计完成，**未修改任何业务代码 / 数据库 / 生产环境**

## 一、产品定位
企业线上获客 + 成交 + 合同 + 支付 + 服务交付平台（官网 + 小程序 + 后台一体化）。

## 二、整体架构
三端（官网 / 小程序 / 后台）+ 统一后端 + 统一 API + 统一数据库 + 统一用户体系（详见 `product-architecture.md`）。

## 三、官网架构
品牌 + 服务 + 案例 + SEO + 获客 + 咨询，不堆订单/日报（详见 `product-architecture.md`）。

## 四、小程序架构
5 Tab（首页/服务/案例/项目/我的）+ 客户中心，原生小程序（详见 `mini-program-architecture.md`）。

## 五、后台架构
现有 24 模块 + 新增服务周期/任务（详见 `admin-architecture.md`）。

## 六、用户流程
新用户 / 老客户 / 工作人员三条流程（详见 `user-flow.md`）。

## 七、客户生命周期
游客 → 线索 → 会员 → 订单 → 合同/实名/支付 → 项目 → 服务周期 → 任务/日报/月报 → 续费。

## 八、订单模型
`Order` + `OrderItem`，后端计价，金额单位分，状态机 8 态。

## 九、合同模型
`Contract` + `ContractVersion` + `ContractSignature`，状态机 8 态，快照固化。

## 十、项目模型
`Project` + `ServicePeriod`（1:N），Order ≠ Project。

## 十一、服务交付模型
Project → ServicePeriod → Task（负责人/截止日期），客户只看进度/日报/月报。

## 十二、日报/月报模型
`ProjectDailyLog`（日报，状态机 3 态）+ `ProjectReport`（月报），客户只读自己的。

## 十三、数据库模型
24 现有模型 + 5 新增（ServicePeriod/Task/Notification/OrderItem/ContractSignature），详见 `database-design.md`。

## 十四、API 架构
统一 `{success, data, message}` + 错误码枚举 + HTTP 状态码约定 + 越权防护规范，详见 `api-design.md`。

## 十五、认证架构
管理员/会员会话分离，JWT + Cookie/Bearer，密钥 fail-fast，AES-256-GCM 数据加密，详见 `auth-permission.md`。

## 十六、权限架构
RBAC 5 角色 + 三层权限（前端/API/资源）+ SUPER_ONLY + 金额权限，详见 `auth-permission.md`。

## 十七、状态机
订单/合同/项目/服务周期/任务/日报全部枚举状态机，详见 `order-state-machine.md` / `contract-state-machine.md` / `project-state-machine.md`。

## 十八、支付流程
后端计价 + 可插拔 Provider + 回调验签 + 幂等 + 金额校验 + Mock fail-closed，详见 `payment-flow.md`。

## 十九、数据迁移方案
增量演进、先备份后迁移、禁止 DROP/TRUNCATE，详见 `migration-plan.md`。

## 二十、缓存方案
当前无缓存（直读库）。若引入：套餐/案例/文章/服务变更需缓存失效；禁止后台 5000 小程序 3000 不一致。

## 二十一、安全方案
- 密钥加密落库、后端权威、越权防护、软删除留痕、限流、Mock fail-closed。
- P0 整改：默认密码、弱 root 密码、¥1 测试套餐、小程序前端缺失、Git 初始化。

## 二十二、日志方案
- 操作日志（AdminOperationLog）：前后快照。
- 登录日志（AdminLoginLog）：成功/失败。
- 支付日志（PaymentLog）：不含密钥。
- 合同版本（ContractVersion）：字段 diff。

## 二十三、通知方案
新增 `Notification` 表：日报/月报/支付/合同/项目/续费通知，小程序端查看（红点/角标）。

## 二十四、前后台数据同步方案
后台改 → 数据库 → 官网/小程序读（唯一数据源）。改价不重编小程序；小程序配置变更需重发。

## 二十五、开发优先级
1. P0 整改（下线测试套餐/改密码/Git 初始化/重建小程序骨架）
2. 数据模型升级（ServicePeriod/Task/Notification + 状态机 + migrations）
3. 业务闭环（PAID→项目自动创建、合同/实名/支付串联、客户中心）
4. 小程序前端完整开发 + 后台补全
5. 安全加固 + 测试 + 性能 + SEO + 上线

## 二十六、预计修改文件（阶段四起）
- `prisma/schema.prisma`、`src/app/api/*`、`src/lib/*`、`miniprogram/`（新建）、`docs/`（本目录已产出）

## 二十七、风险
1. 小程序前端代码缺失（P0，需重建或找回）。
2. 无 Git 版本控制（P1，开发前需 git init）。
3. 无 migrations 历史（P1，需建立 migration 基线）。
4. 状态字段 String/enum 混用，迁移需谨慎。
5. 生产密钥 .env.bak 残留。

## 二十八、回滚方案

- 代码：Git 初始化后按 commit 回滚。
