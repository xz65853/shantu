# 产品架构设计

## 一、产品定位

**桃江闪途（shantu）** 不是「传媒公司官网」，而是一套 **企业线上获客 + 成交 + 合同 + 支付 + 服务交付平台**。

一句话：把「客户看到我们 → 咨询 → 下单 → 签约 → 支付 → 服务交付 → 续费」的完整链路，用一套系统闭环。

## 二、整体架构（三端一库一 API）

```
                ┌─────────────────────────────────────┐
                │           统一后端 (Next.js)           │
                │  统一 API / 统一数据库 / 统一业务模型     │
                └─────────────────────────────────────┘
                        ▲          ▲          ▲
                        │          │          │
              ┌─────────┴──┐ ┌─────┴────┐ ┌───┴─────────┐
              │   官网      │ │ 微信小程序 │ │  管理后台    │
              │ (获客/品牌) │ │(客户中心) │ │ (CRM/交付)  │
              └────────────┘ └──────────┘ └─────────────┘
```

- **官网**：品牌展示、服务/案例、SEO 获客、咨询转化（不堆订单/日报）。
- **微信小程序**：客户服务中心（浏览/下单/实名/合同/支付/项目进度/日报月报/续费）。
- **管理后台**：CRM、订单、合同、项目、服务交付、内容、数据、权限、系统设置。
- **统一用户体系**：`Member` 一张表统一官网客户与小程序客户，可跨端合并。

## 三、官网架构

官网负责「品牌 + 获客 + 转化」，页面信息架构：

```
首页
├─ Hero（一句话定位）
├─ 公司定位
├─ 核心服务（6 大类）
├─ 客户痛点
├─ 解决方案
├─ 成功案例
├─ 合作优势
├─ 合作流程（4 步）
├─ CTA（免费获取方案）
└─ 联系方式
服务列表 / 服务详情
案例列表 / 案例详情
运营干货（博客）
关于我们
联系我们（咨询表单 → 线索）
定价页（套餐展示 → 跳小程序/官网下单）
```

**官网不做**：订单管理、合同签署、日报、项目进度（这些归属小程序客户中心）。

## 四、小程序架构

底部导航（5 个 Tab）：

```
首页      服务      案例      项目      我的
```

核心页面：
- 首页：Banner、服务入口、案例、公告
- 服务：服务列表 → 套餐 → 套餐详情 → 下单
- 案例：案例列表 → 案例详情
- 项目：我的项目 → 项目详情（服务进度 / 日报 / 月报）
- 我的：项目中心、订单、合同、实名、客户资料、联系顾问、续费、售后、设置

## 五、我的页面（客户中心）升级

从「头像 + 昵称 + 订单 + 设置」升级为「我的项目中心」：

```
我的
├─ 我的项目（进行中/已完成）
├─ 我的订单
├─ 我的合同
├─ 我的服务（服务内容/进度）
├─ 服务日报
├─ 月度月报
├─ 客户资料（实名认证）
├─ 联系顾问
├─ 续费入口
├─ 售后/工单
└─ 设置
```

## 六、后台架构

模块（在现有 24 个模块基础上补齐）：

| 域 | 模块 |
| --- | --- |
| 客户 | 线索 CRM、会员、跟进 |
| 交易 | 订单、套餐、优惠券、支付/退款 |
| 履约 | 合同、项目、服务周期、任务、日报、月报 |
| 内容 | 案例、文章、服务、Banner、媒体库、表单 |
| 数据 | 工作台、操作日志、登录日志、导出 |
| 系统 | 管理员、权限、网站设置、小程序设置、AI 配置、回收站 |

## 七、核心业务闭环（最终形态）

**客户侧**：看到 → 了解 → 咨询 → 选套餐 → 下单 → 填资料 → 实名 → 合同确认 → 签署 → 支付 → 订单完成 → 自动建项目 → 服务周期 → 看进度 → 看日报 → 看月报 → 续费。

**员工侧**：线索 → 跟进 → 成单 → 订单 → 合同 → 项目 → 服务周期 → 任务 → 负责人 → 日报 → 月报 → 续费。

## 八、客户生命周期

```
游客 ──咨询──▶ 线索 ──成单──▶ 会员 ──下单──▶ 订单
                                        │
                        ┌───────────────┼───────────────┐
                        ▼               ▼               ▼
                     合同签署        实名认证          支付
                        └───────────────┼───────────────┘
                                        ▼
                                  Project 项目
                                        │
                                  ServicePeriod 服务周期
                                        │
                                  Task 任务 / DailyReport 日报 / MonthlyReport 月报
                                        │
                                        ▼
                                     续费（新订单 → 新周期）
```

## 九、关键设计决策

| 决策 | 说明 |
| --- | --- |
| Order ≠ Project | 订单是交易凭证，项目是服务履约载体，一个客户可多订单/多项目/多周期 |
| ServicePeriod 独立建模 | 支撑「一个项目多个服务周期 + 续费」 |
| Member 统一用户 | 官网 + 小程序同一用户，openid/手机号双登录，支持合并 |
| 后端权威定价 | 前端不传金额，后端查库计价 |
| 状态机集中管理 | 订单/合同/项目/任务/日报全部用枚举状态机 |
| 软删除 + 留痕 | 订单/合同/项目/会员删除走软删除 + 操作日志，可追溯 |
