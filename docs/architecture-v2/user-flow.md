# 用户流程设计

## 一、新用户流程（首次成交）

```
进入官网（SEO/广告/口碑）
   ↓
了解服务 / 案例
   ↓
咨询（提交表单 → 生成线索）
   ↓
顾问跟进 → 推荐套餐
   ↓
进入小程序（扫码）
   ↓
微信登录（wx.login → openid）
   ↓
浏览服务 / 套餐
   ↓
选择套餐 → 下单（后端计价）
   ↓
填写客户资料（姓名/手机/公司）
   ↓
实名认证（微信人脸 / 二要素）
   ↓
合同确认 → 签署（签名图）
   ↓
微信支付（JSAPI）
   ↓
订单 PAID
   ↓
自动创建项目 + 服务周期 + 分配负责人
   ↓
进入「我的项目」查看服务进度
```

**关键约束**：
- 下单需登录（会员）。
- 支付前必须「实名 + 合同已签署」（后端硬校验）。
- 金额以后端数据库为准。

## 二、老客户流程（复购/续费）

```
登录（微信授权 / 手机号+密码）
   ↓
我的项目（进行中项目列表）
   ↓
查看服务进度 / 日报 / 月报
   ↓
服务到期前 → 续费入口
   ↓
选择续费套餐 → 下单 → 支付
   ↓
新增服务周期（同一项目续期）
```

## 三、工作人员流程（履约）

```
后台登录（账号密码，RBAC）
   ↓
线索跟进（CRM）
   ↓
成单 → 创建/确认订单
   ↓
合同生成 / 编辑 / 版本
   ↓
客户签署后 → 订单支付
   ↓
支付成功 → 创建项目
   ↓
设置服务周期 + 服务内容 + 任务 + 负责人
   ↓
每日写日报（短视频/直播/投流/数据/问题/计划）
   ↓
每月写月报（数据汇总 + 总结 + 下月计划）
   ↓
客户在小程序查看
   ↓
到期提醒 → 续费
```

## 四、异常分支流程

| 场景 | 处理 |
| --- | --- |
| 支付回调丢失 | 主动查询订单状态（queryPayment 兜底） |
| 支付重复回调 | 幂等确认（PAID 返回 duplicated） |
| 金额不一致 | 拒绝入账（amount_mismatch） |
| 合同未签就支付 | 后端拒绝（409 请先签署合同） |
| 实名未过就签合同 | 按状态机前置校验（PENDING_REAL_NAME） |
| 客户退款 | 订单 → REFUNDING → REFUNDED，项目状态联动 |
| 客户账号合并 | 官网/小程序同手机号合并，实名/项目归主账号 |
| 项目延期 | 任务 DELAYED + 通知客户 |

## 五、权限边界（流程内嵌）

- 客户只能看**自己的**订单/合同/项目/日报/月报。
- 客户看不到内部备注、负责人内部信息、成本数据。
- 财务角色可看金额，不可看客户隐私（身份证等）。
- 修改订单金额仅超管/财务。
